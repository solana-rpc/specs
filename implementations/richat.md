# Richat

[Richat](https://github.com/lamports-dev/richat) is a streaming server that consumes Geyser data and exposes Solana PubSub over WebSocket as an alternative to the Agave RPC PubSub service.

This page records the source-reviewed surface at Richat revision [`45e8df4`](https://github.com/lamports-dev/richat/tree/45e8df4c674d14c7e81c17a30740e31271ee31a7). `Full` means the reviewed source accepts the standard request and produces the standard notification shape. `Partial` identifies a client-visible difference from the specified Agave behavior. This is a static source review, not a live conformance result.

## Compatibility

Richat implements 16 of Agave's 18 standard subscription lifecycle methods. The two vote methods are not implemented. Block subscriptions are implemented but disabled by default.

## Cross-cutting behavior

Richat uses the same numeric subscription id for clients with identical subscription parameters and tracks ownership per WebSocket connection. Closing a connection removes its subscriptions. Every unsubscribe method uses the same removal path. A current id owned by that connection returns `true`; an unknown, removed, or other-connection id returns `-32602` with `Invalid subscription id.`

Account, program, logs, and signature subscriptions select processed, confirmed, or finalized messages by commitment. Slot, slots-updates, and root subscriptions consume processed slot messages and emit only the matching slot state. Notifications use the standard JSON-RPC subscription envelope. Contextual notifications set the source message slot and omit `apiVersion`.

The service consumes streamed Geyser messages instead of reading an Agave bank in the WebSocket server. Notification timing and completeness therefore depend on the upstream Richat stream and its commitment messages. This review confirms the request dispatch, filters, and serialized shapes in the pinned source. It does not compare a live Richat endpoint with an Agave validator.
