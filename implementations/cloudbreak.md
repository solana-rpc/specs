# Cloudbreak

[Cloudbreak](https://github.com/solana-rpc/cloudbreak) is a PostgreSQL-backed Solana account-state index and JSON-RPC server. It serves account and token queries from configured indexes and streams large `getProgramAccounts` responses.

This page records compatibility at the reviewed Cloudbreak revision [`2dfa7dc`](https://github.com/solana-rpc/cloudbreak/tree/2dfa7dc286d014f503ea201402a838577bf7702b). The matching specs revision is [`5342447`](https://github.com/solana-rpc/specs/tree/534244734fc0a249396ac3ac8448a38fa07c29c9). `Full` means standard valid requests and responses remain compatible. `Partial` identifies a client-visible difference in a standard valid request, response, error, commitment, limit, ordering, or availability contract. Internal storage, stricter rejection of unknown input, and additive behavior do not reduce the rating by themselves.

## Current scope

Cloudbreak claims and wires 17 JSON-RPC methods at the reviewed revision. Fourteen are available on the normal account index. Three require optional index data or configuration.

### Always wired

- `getProgramAccounts`
- `getTokenAccountsByOwner`
- `getTokenAccountsByDelegate`
- `getTokenAccountsByMint` (Cloudbreak extension)
- `getAccountInfo`
- `getMultipleAccounts`
- `getBalance`
- `getTokenAccountBalance`
- `getTokenSupply`
- `getTokenLargestAccounts`
- `getSlot`
- `getHealth`
- `getVersion`
- `getGenesisHash`

### Conditional

- `getVoteAccounts` requires the Vote and Stake programs in the index.
- `simulateTransaction` requires a full unfiltered account index.
- `getLargestAccounts` requires the largest-accounts feature and a populated record.

## Compatibility

| [`getProgramAccounts`](../methods/http/getProgramAccounts.md) | Partial | Standard confirmed and finalized indexed queries work. Token-program GPA accepts only owner, delegate, or mint query shapes. `minContextSlot` is ignored unless `withContext` is true, and a database failure after streaming starts can truncate the JSON body. **Accepted implementation choice:** no native processed support and configured index scope. **Fix Cloudbreak:** enforce `minContextSlot` for every accepted request and preserve a valid JSON-RPC failure contract for stream errors where possible. **Needs live test:** verify order on every query and cache path. |
| [`getTokenAccountsByOwner`](../methods/http/getTokenAccountsByOwner.md) | Partial | Standard confirmed and finalized token queries work for SPL Token and Token-2022. | [`getAccountInfo`](../methods/http/getAccountInfo.md) | Partial | Confirmed and finalized account reads and standard encodings work. `processed` is rejected by default or deliberately downgraded. `minContextSlot` failure uses `-32000` with null data instead of `-32016` with `data.contextSlot`. Oversized legacy binary/base58 output uses `-32602`, not the documented `-32600`. **Fix the specs:** remove the false claim that the method-specific default encoding differs from Agave. **Fix Cloudbreak:** add native processed support and align standard error payloads. **Needs live test:** reproduce the missing-mint `jsonParsed` fallback. |

| [`getTokenLargestAccounts`](../methods/http/getTokenLargestAccounts.md) | Partial ([spec PR #25](https://github.com/solana-rpc/specs/pull/25)) | The method returns up to 20 accounts from a maintained record for configured mints or a live SQL scan otherwise. `processed` is rejected or downgraded, and missing or excluded mint data uses Cloudbreak-specific errors. **Accepted implementation choice:** maintained-record and SQL paths are internal. **Fix Cloudbreak:** add native processed support and align standard mint errors. **Needs live test:** verify stable amount ordering on both paths. |
| [`getSlot`](../methods/http/getSlot.md) | Partial | Confirmed and finalized slots come from stored slot status. `processed` is rejected or downgraded, and `minContextSlot` failure uses `-32000` with null data. **Accepted implementation choice:** stored slot status is an internal source. **Fix Cloudbreak:** add native processed state and align the standard min-context error. |
| [`getHealth`](../methods/http/getHealth.md) | Partial | Cloudbreak reports its indexer's service-health flag instead of validator distance from the cluster tip. | [`getGenesisHash`](../methods/http/getGenesisHash.md) | Full ([spec PR #21](https://github.com/solana-rpc/specs/pull/21)) | The configured cluster genesis hash is returned as the standard base58 string. **Accepted implementation choice:** configuration is the source of a cluster-constant value. |
| [`getVoteAccounts`](../methods/http/getVoteAccounts.md) | Partial, conditional ([spec PR #23](https://github.com/solana-rpc/specs/pull/23)) | The method is available only when Vote and Stake programs are indexed. It builds current and delinquent vote accounts from indexed account state. **Accepted implementation choice:** explicit feature availability. **Fix Cloudbreak:** align any standard request fields, epoch-credit details, and unavailable-method behavior found by conformance tests. |
| [`simulateTransaction`](../methods/http/simulateTransaction.md) | Partial, conditional ([spec PR #20](https://github.com/solana-rpc/specs/pull/20)) | The method is available only with a full unfiltered index. It supports signature verification, recent-blockhash replacement, requested accounts, inner instructions, logs, return data, units, and balance changes. Its bank/runtime view is reconstructed from indexed state rather than an Agave working bank. **Accepted implementation choice:** explicit feature availability. **Needs live test:** run the standard simulation corpus and classify every response and error difference before claiming full compatibility. |
| [`getLargestAccounts`](../methods/http/getLargestAccounts.md) | Partial, conditional ([spec PR #17](https://github.com/solana-rpc/specs/pull/17)) | The method requires the largest-accounts feature and a populated record. It supports circulating and non-circulating filters but returns `-32602` when disabled and an internal error when the record is absent. **Accepted implementation choice:** optional feature availability. **Fix Cloudbreak:** define and align the enabled-but-not-ready availability contract. |

## Cross-cutting behavior

Cloudbreak supports confirmed and finalized state. Its default `processed-commitment = "reject"` policy returns `-32003`. The optional `use-confirmed` policy accepts a request for `processed` but serves confirmed state. This downgrade is deliberate and must not be described as native processed support. Native processed support remains roadmap work only for `getAccountInfo`, `getBalance`, `getMultipleAccounts`, and `getSlot`; reviewers explicitly rejected it for `getProgramAccounts` and `getTokenAccountsByOwner`.

Cloudbreak's common error serializer does not reproduce the Agave payload contract. Numeric codes can differ, `data` is always null, and messages may be either Cloudbreak tokens or interpolated text. The existing repository introduction overstates this as every message being an opaque SNAKE_CASE token. **Fix the specs:** narrow that statement. **Fix Cloudbreak:** align codes, messages, and data for standard errors before methods with those errors can be rated full.

Cloudbreak uses PostgreSQL, configured program indexes, caches, and streamed responses. These are implementation choices. They affect compatibility only when they change a standard valid request, ordering, availability, or complete JSON response.
