# Cloudbreak

[Cloudbreak](https://github.com/solana-rpc/cloudbreak) is a PostgreSQL-backed Solana account-state index and JSON-RPC server. It serves account and token queries from configured indexes and streams large `getProgramAccounts` responses.

This page records compatibility at the reviewed Cloudbreak revision [`4b2f28e`](https://github.com/solana-rpc/cloudbreak/tree/4b2f28e40b0c984538a57874c4bac3697fccaaec). The matching specs revision is [`5342447`](https://github.com/solana-rpc/specs/tree/534244734fc0a249396ac3ac8448a38fa07c29c9). `Full` means standard valid requests and responses remain compatible. `Partial` identifies a client-visible difference in a standard valid request, response, error, commitment, limit, ordering, or availability contract. Internal storage, stricter rejection of unknown input, and additive behavior do not reduce the rating by themselves.

The first review of this page was written at revision [`2dfa7dc`](https://github.com/solana-rpc/cloudbreak/tree/2dfa7dc286d014f503ea201402a838577bf7702b) from source. Since then Cloudbreak merged [PR #51](https://github.com/solana-rpc/cloudbreak/pull/51), which fixes most of the items this page raised, and the remaining claims were tested on the wire against Agave. Every rating below now rests on a captured comparison, or on a stated reason why no comparison exists. Read **Evidence and open items** before you quote a rating: two roadmap items are still blocked, and three contracts could not be compared against Agave at all.

## Current scope

Cloudbreak claims and wires 18 JSON-RPC methods at the reviewed revision. Thirteen are available on the normal account index. Five require optional index data or configuration.

### Always wired

- `getProgramAccounts`
- `getTokenAccountsByOwner`
- `getTokenAccountsByDelegate`
- `getTokenAccountsByMint` (Cloudbreak extension)
- `getAccountInfo`
- `getMultipleAccounts`
- `getBalance`
- `getTokenAccountBalance`
- `getTokenSupply`
- `getSlot`
- `getHealth`
- `getVersion`
- `getGenesisHash`

### Conditional

- `getVoteAccounts` requires the Vote and Stake programs in the index.
- `simulateTransaction` requires a full unfiltered account index.
- `getLargestAccounts` requires the largest-accounts feature and a populated record.
- `getTokenLargestAccounts` requires the token-largest-accounts feature on the indexer and the API, and serves only the mints the indexer tracks.
- `getSupply` requires the supply feature on the indexer and the API. It is new since the first review and is **not rated here**: its method page is still [spec PR #61](https://github.com/solana-rpc/specs/pull/61) and no evidence was gathered for it.

A conditional method that is disabled, or whose index scope is wrong, returns `-32601 Method not found`. That contract was checked on every one of them.

## Compatibility

## Cross-cutting behavior

Cloudbreak supports confirmed and finalized state on every method. The optional `[processed-accounts]` module adds native `processed` for `getAccountInfo`, `getMultipleAccounts`, `getBalance`, `getTokenAccountBalance`, `getTokenSupply`, and `getSlot`. Every other method handles `processed` through the deployment-wide `processed-commitment` policy. The default `reject` policy returns `-32602 Processed commitment level is not supported`. The optional `use-confirmed` policy accepts the request and serves confirmed state. This downgrade is deliberate and must not be described as native processed support. Both policies were exercised on the wire, and neither affects the natively supported methods. Cloudbreak intentionally excludes native processed from the broad `getProgramAccounts`, `getTokenAccountsByOwner`, and `getTokenAccountsByDelegate` queries, and from `getTokenLargestAccounts`.

The processed rejection used `-32003`, which is Agave's `TransactionSignatureVerificationFailure`. It now uses the standard `-32602`, and Cloudbreak no longer returns `-32003` for anything. **Fix the specs:** `errors/codes.yaml` can drop the `-32003` collision warning.

Cloudbreak's error envelope now follows the Agave payload contract. The `message` is Agave's text, and `data` carries `contextSlot` for a min-context failure and `numSlotsBehind` for an unhealthy node. The SNAKE_CASE tokens are gone from the wire, including on the filter-verification path, where the errors are byte-identical to Agave down to `Invalid param: DataTooLarge` and `Invalid param: Base58DecodeError(InvalidCharacter { character: '0', index: 0 })`. **Fix the specs:** the repository introduction still says every message is an opaque SNAKE_CASE token with null `data`. That statement is wrong at this revision. Replace it with a pointer to the accepted differences below.

Cloudbreak uses PostgreSQL, configured program indexes, caches, and streamed responses. These are implementation choices. They affect compatibility only when they change a standard valid request, ordering, availability, or complete JSON response.

## Accepted differences from Agave

These differences are deliberate and are not open work. They are the whole set of client-visible differences the live comparison found, other than the per-method notes above.

| Difference | Where | Why it stands |
|---|---|---|
| `-32602 Processed commitment level is not supported` | Every method without native processed support, under the default `reject` policy | Agave has no equivalent state. The code is the standard `-32602`, so it does not collide with an Agave meaning. |
| `-32010 … excluded from account secondary indexes; this RPC method unavailable for key` | `getProgramAccounts`, `getTokenAccountsByOwner`, `getTokenAccountsByDelegate`, `getTokenAccountsByMint` on a program outside the indexer filter; `getTokenLargestAccounts` on a mint the indexer does not track | The wire form is Agave's, the condition is Cloudbreak's: the configured index scope, not a secondary-index exclusion. The text matches upstream Agave exactly. |
| A point read on an excluded owner returns `value: null` or `0` | `getAccountInfo`, `getMultipleAccounts`, `getBalance` | The indexer never writes the row, so the read takes the not-found path before any exclusion check. Cloudbreak cannot tell "not indexed" from "does not exist" here. The same owner is an error on `getProgramAccounts`, so a client sees an exclusion on the broad queries and a missing account on the point reads. |
| `-32005 Node is unhealthy` with `data.numSlotsBehind: null` | `getHealth`, and every account and token method while the indexer health flag is false | Cloudbreak gates reads on its own indexer health. Agave returns this from `getHealth` only. `getSlot` stays ungated. |
| HTTP 503 carrying the same `-32005` body | Any of the above, when `unhealthy-response = "http-unavailable"` | An operator option, so load balancers can drop an unhealthy node. The JSON-RPC body is identical in both modes. The default is HTTP 200. |
| `Invalid param: could not find mint` or `Invalid param: Token mint could not be unpacked` where Agave says `not a Token account` or `not a Token mint` | `getTokenAccountBalance` on a token-program account that is not a token account; `getTokenAccountsByOwner` and `ByDelegate` with `{mint}` naming a non-token-owned account | Both queries read only the bytes they need, with partition pruning. Naming the case the way Agave does costs a second lookup. |
| `-32601 Method not found` | `getVoteAccounts`, `simulateTransaction`, `getSupply`, `getLargestAccounts`, `getTokenLargestAccounts` when the feature is off or the index scope is wrong | Agave always serves these methods. Cloudbreak serves them only when configured, and says so with the standard code and text. |
| `-32603 Internal error` where Agave returns `-32012 scan aborted` | `getProgramAccounts`, the token queries, on a query timeout or database error | Cloudbreak cannot map every database failure to a scan failure. Revisit if clients need `-32012`. |
| No filter-count cap | `getProgramAccounts` with five or more filters | Agave caps at four. Cloudbreak serves the request. This is additive capacity, accepted by this page. |
| A connection abort with no JSON-RPC body | `getProgramAccounts` and `getTokenAccountsByMint`, only when `gpa-stream-batch-size` is set | A failure after the response has started cannot be a JSON-RPC error. The default is a single batch, where every failure is a normal error body. Client libraries raise on the abort rather than returning a truncated value. |
| `-32602` with Cloudbreak message text | `simulateTransaction` on malformed base64 or a truncated transaction | The code is the one the method page pins. The page does not name the text for these cases. |
| `-32602 Invalid params` | `getProgramAccounts` on a token program without an owner, delegate, or mint memcmp | Cloudbreak serves only indexed token query shapes. |
| The `ValueCmp` filter | `getProgramAccounts` and the token queries | A Cloudbreak filter with no Agave equivalent, proposed in [PR #27](https://github.com/solana-rpc/specs/pull/27). Additive, and it does not disturb result order. |
| `Missing parameter at index N`, `Invalid parameter: <serde error>` | Every method, on a missing or malformed positional parameter | The wording comes from the JSON-RPC layer and each implementation's Rust types. |

## Evidence and open items

The results on this page come from a live comparison campaign run between 2026-09-18 and 2026-09-21, against a three-node staging deployment of the reviewed build. The Agave references are Triton-operated mainnet nodes at `4.2.2` and `4.3.0-rc.0`. Three index scopes were needed, because the index scope decides which methods answer at all: a token-only scope, a scope with the token programs excluded, and a full unfiltered scope. A fourth run excluded one small program deliberately, to produce the excluded-index and feature-disabled cases.

Two caveats apply to exact-text comparisons. The reference nodes are Triton builds, so their `-32010` message appends a documentation sentence that upstream Agave does not send; where a text differs that way, upstream source is the baseline. And a deployment running a build older than this revision still sends the SNAKE_CASE messages this page says are gone, so read a wire capture against the revision that produced it.

These items are open, and this page does not claim them:

- **Tied-balance ordering on `getTokenLargestAccounts`.** No mainnet mint with two holders at an identical amount has been found, so the ordering rule for ties is unverified.
- **Schema validation for `getTokenAccountsByMint` and `ValueCmp`.** Blocked on [PR #28](https://github.com/solana-rpc/specs/pull/28) and [PR #27](https://github.com/solana-rpc/specs/pull/27).
- **`getLargestAccounts` values.** No Agave reference node answers the method on mainnet, so only Cloudbreak's own contract is verified.
- **`getTokenAccountsByDelegate` values.** No Agave node in the reference fleet indexes the token delegate.
- **The missing-mint `jsonParsed` fallback.** Not producible on a mainnet index; closed on source review, not on a captured response.
- **`getSupply`.** Wired at this revision, deliberately unrated, and waiting for [PR #61](https://github.com/solana-rpc/specs/pull/61).
