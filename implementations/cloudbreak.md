# Cloudbreak

[Cloudbreak](https://github.com/solana-rpc/cloudbreak) is a PostgreSQL-backed Solana account-state index and JSON-RPC server. It serves account and token queries from configured indexes and streams large `getProgramAccounts` responses.

This page records compatibility at the reviewed Cloudbreak revision [`2dfa7dc`](https://github.com/solana-rpc/cloudbreak/tree/2dfa7dc286d014f503ea201402a838577bf7702b). The matching specs revision is [`5342447`](https://github.com/solana-rpc/specs/tree/534244734fc0a249396ac3ac8448a38fa07c29c9). `Full` means standard valid requests and responses remain compatible. `Partial` identifies a client-visible difference in a standard valid request, response, error, commitment, limit, ordering, or availability contract. Internal storage, stricter rejection of unknown input, and additive behavior do not reduce the rating by themselves.

## Current scope

Cloudbreak claims and wires 17 JSON-RPC methods at the reviewed revision. Fourteen are available on the normal account index. Three require optional index data or configuration.

### Always wired

- `getProgramAccounts`
- `getTokenAccountsByOwner`
- `getTokenAccountsByDelegate`
- `getTokenAccountsByMint` (Cloudbreak extension)
- `getAccountInfo`
- `getMultipleAccounts`
- `getBalance`
- `getTokenAccountBalance`
- `getTokenSupply`
- `getTokenLargestAccounts`
- `getSlot`
- `getHealth`
- `getVersion`
- `getGenesisHash`

### Conditional

- `getVoteAccounts` requires the Vote and Stake programs in the index.
- `simulateTransaction` requires a full unfiltered account index.
- `getLargestAccounts` requires the largest-accounts feature and a populated record.

## Compatibility

An adjacent `spec PR` link means the method page is absent from the specs main branch and is proposed in that draft. It does not mean Cloudbreak lacks the method. The method name links directly to its specs page when that page exists on main.

| `getTokenSupply` | Partial ([spec PR #22](https://github.com/solana-rpc/specs/pull/22)) | SPL Token and Token-2022 supplies use the standard response type. `processed` is rejected or downgraded, and missing, excluded, or malformed mint data uses Cloudbreak-specific error payloads. **Fix Cloudbreak:** decide native processed support and align standard mint errors. |
| `getTokenLargestAccounts` | Partial ([spec PR #25](https://github.com/solana-rpc/specs/pull/25)) | The method returns up to 20 accounts from a maintained record for configured mints or a live SQL scan otherwise. `processed` is rejected or downgraded, and missing or excluded mint data uses Cloudbreak-specific errors. **Accepted implementation choice:** maintained-record and SQL paths are internal. **Fix Cloudbreak:** decide native processed support and align standard mint errors. **Needs live test:** verify stable amount ordering on both paths. |
| [`getSlot`](../methods/http/getSlot.md) | Partial | Confirmed and finalized slots come from stored slot status. `processed` is rejected or downgraded, and `minContextSlot` failure uses `-32000` with null data. **Accepted implementation choice:** stored slot status is an internal source. **Fix Cloudbreak:** add native processed state and align the standard min-context error. |
| [`getHealth`](../methods/http/getHealth.md) | Partial | Cloudbreak reports its indexer's service-health flag instead of validator distance from the cluster tip. The reviewed handler returns `-32603` with null data when unhealthy rather than the standard `-32005` payload, and `getSlot` is not subject to the account-method health gate. **Accepted implementation choice:** service-local health semantics. **Fix Cloudbreak:** use the common unhealthy error code and payload unless the standard explicitly permits a product-local contract. |
| `getVersion` | Full ([spec PR #19](https://github.com/solana-rpc/specs/pull/19)) | The standard `solana-core` string is present. Cloudbreak uses a composite `<upstream>-cloudbreak<version>` value, which remains valid standard output and exposes useful implementation identity. **Accepted implementation choice:** composite version text. |
| `getGenesisHash` | Full ([spec PR #21](https://github.com/solana-rpc/specs/pull/21)) | The configured cluster genesis hash is returned as the standard base58 string. **Accepted implementation choice:** configuration is the source of a cluster-constant value. |
| `getVoteAccounts` | Partial, conditional ([spec PR #23](https://github.com/solana-rpc/specs/pull/23)) | The method is available only when Vote and Stake programs are indexed. It builds current and delinquent vote accounts from indexed account state, but accepts and ignores `commitment` and always uses finalized state. **Accepted implementation choice:** explicit feature availability. **Fix Cloudbreak:** honor the requested commitment and align any epoch-credit or unavailable-method differences found by conformance tests. |
| `simulateTransaction` | Partial, conditional ([spec PR #20](https://github.com/solana-rpc/specs/pull/20)) | The method is available only with a full unfiltered index. It supports signature verification, recent-blockhash replacement, requested accounts, inner instructions, logs, return data, units, and balance changes. It rejects or downgrades `processed`, returns `-32000` with null data for a min-context failure, and reconstructs its bank/runtime view from indexed state rather than an Agave working bank. **Accepted implementation choice:** explicit feature availability. **Fix Cloudbreak:** align the standard commitment and min-context error contract. **Needs live test:** run the standard simulation corpus and classify every response and error difference before claiming full compatibility. |
| `getLargestAccounts` | Partial, conditional ([spec PR #17](https://github.com/solana-rpc/specs/pull/17)) | The method requires the largest-accounts feature and a populated record. It supports circulating and non-circulating filters but ignores `sortResults` and always returns its maintained descending order. It returns `-32602` when disabled and an internal error when the record is absent. **Accepted implementation choice:** optional feature availability. **Fix Cloudbreak:** honor `sortResults` and define the enabled-but-not-ready availability contract, or propose a narrower standard contract that removes unstable ordering. |

## Cross-cutting behavior

Cloudbreak supports confirmed and finalized state. Its default `processed-commitment = "reject"` policy returns `-32003`. The optional `use-confirmed` policy accepts a request for `processed` but serves confirmed state. This downgrade is deliberate and must not be described as native processed support. Native processed support is roadmap work for `getAccountInfo`, `getBalance`, `getMultipleAccounts`, and `getSlot`. Cloudbreak intentionally excludes it from the broad `getProgramAccounts`, `getTokenAccountsByOwner`, and `getTokenAccountsByDelegate` queries. The processed-state policy for the point and bounded token methods still needs an explicit product decision.

Cloudbreak's common error serializer does not reproduce the Agave payload contract. Numeric codes can differ, `data` is always null, and messages may be either Cloudbreak tokens or interpolated text. The existing repository introduction overstates this as every message being an opaque SNAKE_CASE token. **Fix the specs:** narrow that statement. **Fix Cloudbreak:** align codes, messages, and data for standard errors before methods with those errors can be rated full.

Cloudbreak uses PostgreSQL, configured program indexes, caches, and streamed responses. These are implementation choices. They affect compatibility only when they change a standard valid request, ordering, availability, or complete JSON response.
